# عقد API — الإصدار `v1`

الواجهة تتحدث إلى عقد ثابت، ولا تعرف شيئاً عن المزوّد. تبديل Groq بمزوّد آخر تعديل في الخادم فقط، ما دام هذا العقد محفوظاً.

## المسارات

| المسار | الطريقة | الوظيفة |
| --- | --- | --- |
| `/api/v1/status` | `GET` | هل الوسيط مهيّأ؟ لا يكشف أي سر |
| `/api/v1/ai` | `POST` | تشغيل أداة واحدة |
| `/api/v1/ai` | `OPTIONS` | preflight لأصل مسموح صراحةً |

المساران القديمان `/api/status` و`/api/ai` يعملان أيضاً للتوافق. كل رد يحمل الترويسة `X-API-Version: v1`.

## `GET /api/v1/status`

</div>

```json
{ "configured": true, "provider": "Groq" }
```

<div dir="rtl">

`configured` يعني وجود مفتاح مزوّد **و** رمز وصول صالح الطول. لا يعني أن المفتاح صالح فعلياً؛ التحقق الحقيقي يحدث عند أول طلب.

## `POST /api/v1/ai`

الترويسات المطلوبة:

- `Content-Type: application/json`
- `x-lek-access: <رمز وصول التطبيق>` — ليس مفتاح المزوّد

الجسم:

</div>

```json
{
  "tool": "marketing",
  "consent": true,
  "input": {
    "product": "نبتة",
    "audience": "أصحاب المساحات الصغيرة",
    "benefit": "نباتات داخلية سهلة العناية",
    "platform": "instagram",
    "tone": "friendly",
    "language": "ar"
  }
}
```

<div dir="rtl">

`consent` يجب أن يكون `true` صراحةً. أي قيمة أخرى تُرفض بـ 400.

### حدود المدخلات

| الأداة | الحقول | الحد |
| --- | --- | --- |
| `marketing` | `product` ≤80، `audience` ≤160، `benefit` ≤400 | `platform`: instagram/linkedin/x · `tone`: friendly/professional/bold · `language`: ar/en |
| `summary` | `text` بين 80 و12,000 حرف | `length`: short/medium/detailed · `language`: ar/en |
| `code` | `code` بين 1 و12,000 حرف | `language`: javascript/typescript/json |

حجم الجسم كله ≤64,000 بايت، ويُقاس أثناء القراءة لا من الترويسة فقط.

### الرد الناجح

</div>

```json
{ "result": { "mode": "ai", "variants": [{ "id": "v1", "label": "…", "text": "…" }] } }
```

<div dir="rtl">

`mode` يُضاف في الخادم دائماً. في أداة `marketing` على منصة `x` يُرفض أي اقتراح يتجاوز 280 حرفاً بـ 502 (`output`). إحصاءات التلخيص تُحسب محلياً من النص الأصلي، ولا تُقبل من النموذج. أي `formatted` يعيده النموذج لأداة الكود يُحذف؛ التنسيق الآمن يأتي من المحرّك المحلي فقط.

### الرد الخاطئ

</div>

```json
{ "error": { "code": "rate-limit", "message": "…" } }
```

<div dir="rtl">

| HTTP | `code` | المعنى |
| --- | --- | --- |
| 404 | `method` | مسار غير معروف |
| 405 | `method` | طريقة غير مدعومة |
| 403 | `origin` | أصل غير مسموح |
| 415 | `content-type` | ليس JSON |
| 503 | `not-configured` | الوسيط غير مهيّأ؛ المحلي يعمل |
| 401 | `access` | رمز وصول خاطئ |
| 429 | `rate-limit` | حد الدقيقة أو اليوم |
| 413 / 400 | `body` | جسم كبير أو غير صالح |
| 400 | `input` | حقول خارج الحدود أو بلا موافقة |
| 503 | `model` | اسم نموذج غير صالح |
| 429 | `provider-limit` | حصة المزوّد |
| 503 | `provider-auth` | مفتاح المزوّد يحتاج مراجعة |
| 502 | `provider-request` | المزوّد رفض إعدادات الطلب |
| 502 | `provider` | خطأ آخر عند المزوّد |
| 502 | `output` | نتيجة لا تطابق البنية |
| 504 | `timeout` | مهلة أو تعذّر وصول |

`code` ثابت وقابل للقراءة آلياً. `message` عربي للمستخدم وقد يتغير؛ لا تبنِ منطقاً عليه.

## الحماية

- **رمز وصول** يقارَن زمنياً ثابتاً عبر SHA-256 + `timingSafeEqual`.
- **6 طلبات/دقيقة** لكل عميل لحماية الخادم من تدفق الطلبات قبل فحص الجسم، وسقف يومي `AI_DAILY_LIMIT` (افتراضي 40، أقصى 1000) يُستهلك فقط للطلبات الصالحة الجاهزة للإرسال إلى المزوّد.
- **سقف tokens**: `AI_MAX_TOKENS` افتراضي 4096، مقبول بين 1024 و8192. أي قيمة خارجه تُتجاهل.
- **مهلة**: `AI_TIMEOUT_MS` افتراضي 24,000، بين 1000 و25,000.
- **إعادة محاولة واحدة** عند 429 من المزوّد، باحترام `Retry-After` وبحد أعلى ثانيتين، وفقط إن كانت تتسع داخل المهلة.
- **Origin allowlist**: `AI_ALLOWED_ORIGINS` قائمة أصول مفصولة بفواصل. فارغة = نفس الأصل فقط.

> CORS ليس حاجزاً أمنياً. `curl` يتجاوز أي ترويسة Origin. الذي يحمي الحصة فعلاً هو رمز الوصول + حد الطلبات + سقف tokens. لا تعتمد على allowlist وحده.

- العدادات في ذاكرة العملية، **ليست حصة موزعة**. نسخ serverless متعددة لا تتشاركها، وتُصفّر عند إعادة التشغيل. للإطلاق العام أضف حصة مركزية ومصادقة حقيقية.

## إضافة أداة جديدة

1. أضف المعرّف إلى `shared/tools.ts`.
2. أنشئ وحدة الخادم في `server/tools/<id>.ts` تحقّق المدخلات، تبني الـ prompt، تتحقق من النتيجة، وتضيف ما يلزم.
3. سجّلها بسطر واحد في `server/tools/index.ts`.
4. أنشئ الصفحة في `src/pages/` وسجّلها بسطر واحد في `src/tools/index.ts`.

التنقل والبحث والتوجيه وبطاقات الرئيسية ومرشّحات المكتبة كلها مشتقة من السجل. لا تعديل في النواة.

## إضافة مزوّد جديد

1. أنشئ `server/providers/<id>.ts` ينفّذ واجهة `Provider`.
2. سجّله في `server/providers/index.ts`.
3. اضبط `AI_PROVIDER=<id>` ومفتاحه في بيئة الخادم.

الواجهة لا تتغير، والعقد يبقى `v1`.
